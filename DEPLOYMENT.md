# Deployment, backups and launch checklist

How to install and run **Creator Studio Assistant** (the AI YouTube Employee) for daily use, keep its data safe, and check it before relying on it. Written for beginners; every command is typed in a terminal (Windows: *PowerShell* or *Terminal*) inside the project folder.

> **What "deployment" means here.** This is a **local-first app**: it runs on your own Windows computer and only that computer can open it (it listens on `localhost`). It is **not** built to be a public website. Don't put it on a server on the internet or open its port in your router — see [§7](#7-what-not-to-do).

Related documents: setup details and troubleshooting in [README.md](README.md), security rules in [SECURITY.md](SECURITY.md), costs and service limits in [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md) §3.

## 1. Requirements

| | Minimum (tested) | Notes |
|---|---|---|
| Computer | Windows 10/11, 2 CPU cores, 4 GB RAM, no graphics card | Tested on an i5-3210M with 3.9 GB RAM. More RAM and cores make AI and rendering faster. |
| Disk | 10 GB free + space for your videos | Videos, exports and caches live in `storage/`. Speech models ~150 MB, the default AI model ~1 GB. |
| Software | Node.js 24 LTS, Git, FFmpeg (full build), uv, Ollama | Install commands: README › Prerequisites. |
| Internet | Only for installing, YouTube, and optional services | Everything else works offline. |

## 2. First installation (step by step)

1. **Get the code** (once): `git clone <your repository URL>` and open the folder in a terminal.
2. **Install the app's packages:** `npm install`
3. **Create your settings file with fresh secrets:** `npm run setup:env` — this writes `.env` (never overwrites an existing one). Keep `.env` private; it is ignored by Git.
4. **Install the media worker (Python):** `npm run worker:setup`
5. **Create the database:** `npm run db:deploy`
6. **Download the AI model** (default, ~1 GB): `ollama pull qwen2.5:1.5b` — then make sure `OLLAMA_MODEL="qwen2.5:1.5b"` is in `.env`.
7. **Build the app for daily use:** `npm run build` (a few minutes).
8. **Start everything:** `npm run start:all` — or double-click `scripts\start-windows.cmd` (it builds first if needed and opens your browser). Keep the window open while you use the app; press **Ctrl+C** or close the window to stop it.
9. Open **http://localhost:3000**, create your **owner account** (only one account can ever be created), and check *Settings › System status* — everything you need should be green or explained.

Optional, when you want them:
- **YouTube publishing:** README › *Google Cloud setup* (free, ~20 minutes).
- **Stock footage for the video generator:** a free Pexels key (README › *Original video generator*).

> If PowerShell refuses `npm` ("running scripts is disabled"), type `npm.cmd` instead of `npm` in every command, or use the start script — no need to change Windows' security settings.

> `npm run dev:all` is for developing the app (slower, recompiles on every change). For daily use, use `npm run start:all`.

## 3. Updating to a new version

1. Stop the app (Ctrl+C) and **make a backup** first: `npm run backup`
2. `git pull`
3. `npm install` and `npm run worker:setup`
4. `npm run db:deploy` (applies new database changes; your data is kept)
5. Compare `.env.example` with your `.env` and add any new settings you want to change (missing ones use safe defaults).
6. `npm run build`, then start again with `npm run start:all`.

## 4. Environment variable checklist

`.env` is read by the app and both workers. `npm run setup:env` fills in the three secrets. The full list with explanations is in `.env.example`.

**Required — the app won't start properly without them**

| Variable | What it is | Secret? | How to set it |
|---|---|---|---|
| `BETTER_AUTH_SECRET` | Signs your login sessions | **Yes** | Generated by `setup:env`. Changing it signs you out. |
| `WORKER_SHARED_SECRET` | Lets the workers talk to the app | **Yes** | Generated by `setup:env`. |
| `TOKEN_ENCRYPTION_KEY` | Encrypts YouTube sign-in tokens | **Yes** | Generated by `setup:env`. **Losing or changing it means reconnecting your channels.** Back it up (§5). |
| `BETTER_AUTH_URL` | Address of the app | No | Keep `http://localhost:3000`. |
| `DATABASE_URL`, `STORAGE_DIR` | Where data lives | No | Defaults `./data/app.db` and `./storage`. Use an absolute path to keep media on another drive. |
| `OLLAMA_MODEL` | The local AI model | No | `qwen2.5:1.5b` on 4–8 GB RAM; a larger model writes better text if you have the RAM. |

**Needed only for a feature**

| Feature | Variables | Secret? | Notes |
|---|---|---|---|
| YouTube channels and uploads | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | Client secret: **yes** | Free Google Cloud project (README). `YOUTUBE_API_AUDITED` stays `false` until Google audits your project (uploads are private until then). |
| Stock footage | `PEXELS_API_KEY`, `PIXABAY_API_KEY` | **Yes** | Free keys. Without them the generator uses your own clips. |
| Other AI providers | `GEMINI_API_KEY` + `GEMINI_MODEL`, or `OPENAI_COMPAT_*` | **Yes** | Optional. Gemini's free tier may use your prompts to improve Google products. Don't point `OPENAI_COMPAT_BASE_URL` at a paid service unless you mean to pay. |
| Narration voice | `TTS_PROVIDER`, `TTS_VOICE` | No | Windows voices by default; Kokoro is optional and untested. |

**Tuning (safe defaults)**: `RENDER_THREADS` (set `1` if the computer gets sluggish while videos are processed), `WHISPER_MODEL`, `WHISPER_KEEP_LOADED`, `MAX_UPLOAD_MB`, `MAX_VIDEO_DURATION_MIN`, `MAINTENANCE_INTERVAL_MIN`, `STOCK_CACHE_DAYS`, `LOG_LEVEL`, clip and packaging limits — see `.env.example`.

**Must NOT be in a real `.env`**: `GOOGLE_API_TEST_BASE_URL` (for automated tests only; a production run ignores it and *System status* reports it).

Checks you can run any time:
- *Settings › System status* in the app — says what's configured and what's missing, never shows secret values.
- `npm run check:secrets` (after `npm run build`) — confirms no secret value ended up in the files sent to the browser and that Git would not pick up `.env`, databases, storage or credential files.

## 5. Backups and recovery

**What holds your data**

| What | Where | Can it be rebuilt? |
|---|---|---|
| Database (videos list, transcripts' index, clips, Shorts, packaging, channels, jobs) | `data/app.db` | **No** — back it up. |
| Your videos, exports, thumbnails, narration, transcripts | `storage/` | **No** for originals you don't have elsewhere. |
| Secrets | `.env` | Partly: without `TOKEN_ENCRYPTION_KEY` you must reconnect YouTube; without `BETTER_AUTH_SECRET` you're signed out. |
| AI and speech models, stock clips, search cache | `models/`, `storage/stock-cache/` | Yes (downloaded again when needed). |

**Making a backup** (safe while the app is running — the database is copied with SQLite's online backup and checked):

```bash
npm run backup
```

- Writes `backups/backup-<date>-<time>/` with `app.db`, `storage/` (without temporary files) and `manifest.json`.
- `npm run backup -- --no-media` — database and small files only (fast, small; videos not included).
- `npm run backup -- --out D:\Backups` — write to another drive (recommended: an external drive or a synced folder).
- `npm run backup -- --include-env` — also copies `.env` as `env.backup`. **That backup then contains your secrets**; keep it private. Otherwise, keep a copy of `.env` somewhere safe yourself (e.g. a password manager).

Recommended routine: `npm run backup -- --out <external drive>` **weekly**, a `--no-media` backup **before every update**, and keep at least two older backups. A backup on the same disk doesn't protect against a broken disk.

**Restoring a backup**

1. Stop the app (Ctrl+C).
2. `npm run restore -- backups\backup-20261014-201500 --yes` (use your folder's name). Nothing is deleted: your current `data/` database and `storage/` folder are moved to `backups/before-restore-<time>/` first, so a restore can be undone.
3. `npm run db:deploy` (in case the backup is from an older version), then start the app.
4. If you also lost `.env`: restore `env.backup` (rename it to `.env`) — or run `npm run setup:env`, sign in again, and reconnect YouTube channels in *Settings › Channels*.

**Other recovery situations**

| Situation | What to do |
|---|---|
| Forgot the owner password | Stop the app, `npm run auth:reset-password`, start again. |
| A job seems stuck | It's retried automatically when its worker stops responding (within about a minute while any worker runs). You can cancel it in the activity panel and retry. |
| The computer crashed or lost power mid-job | Just start the app again: unfinished jobs are retried (a YouTube upload continues where it stopped); half-written files are removed by the next run of that job or by housekeeping. |
| Disk filling up | Housekeeping removes unused files every hour (old narration takes, replaced clips, stock clips unused for `STOCK_CACHE_DAYS`, abandoned uploads, leftovers of deleted items). Delete videos you no longer need in *Videos*. |
| Database damaged ("malformed" errors) | Stop the app and restore the latest backup. |

## 6. Launch checklist

Tick these before you rely on the app for your channel. "Verified" means it was tested in this project on the owner's PC; the other items **need your credentials or a real-world test** and are not yet proven.

**Installation and safety**
- [ ] `npm run check` and `npm run worker:test` pass; `npm run build` succeeds.
- [ ] `npm run check:secrets` passes; `git status` shows no `.env`, `data/`, `storage/` or `backups/`.
- [ ] *Settings › System status*: no red items.
- [ ] Owner account created with a strong password (12+ characters).
- [ ] A backup made **and restored once on purpose** (so you know it works), with `.env` stored safely.
- [ ] The app opens only on this computer (http://localhost:3000); nobody else can reach it.

**Features — verified with automated tests and real local runs**
- [x] Sign-in, sessions, single owner, rate-limited login, password change signs out other devices.
- [x] Uploads (resumable, size/format checks), library, processing, previews.
- [x] Local transcription and AI Clip Finder (real speech and real local AI model).
- [x] Shorts editor and MP4 export (real recording; captions in sync).
- [x] AI packaging with the local model (titles, descriptions, hashtags, hooks, thumbnail mock-ups).
- [x] Original video generator: real AI script, Windows narration, own footage, FFmpeg render (two real videos produced).
- [x] Background jobs: retries, crash recovery, no duplicate jobs from double clicks, housekeeping.
- [x] Backups and restore (tested on a copy, also while the app was running).

**Needs your credentials or a real-world test (not verified yet)**
- [ ] **YouTube:** connect a real channel, upload a *private* test video and a Short with a thumbnail, check it in YouTube Studio, disconnect and reconnect. (Only tested against a local stand-in of Google's servers.)

- [ ] **Stock footage:** add a free Pexels key, generate a video with stock clips, check the credits link to the right Pexels pages. (Only tested with simulated Pexels/Pixabay responses.)

## 7. What not to do

- **Don't expose the app to the internet** (port forwarding, cloud server, tunnelling tools). It is designed for one person on one computer: the worker connection, rate limits and cookie settings assume `localhost`, and there is no HTTPS. A public deployment would need HTTPS, a reverse proxy that sets the client IP, and a fresh security review.
- **Don't share or commit `.env`** or a backup made with `--include-env`.
- **Don't delete `TOKEN_ENCRYPTION_KEY`** unless you're ready to reconnect your YouTube channels.
- **Don't add paid services** (a paid AI API in `OPENAI_COMPAT_BASE_URL`, paid stock or video-generation services) unless you decide to pay for them.

## 8. Running costs

| Item | Cost |
|---|---|
| The app, Ollama, faster-whisper, FFmpeg, Windows voices | Free (open-source / built into Windows). |
| YouTube Data API | Free within Google's quota (10,000 units/day; 100 uploads/day). |
| Google Cloud project for OAuth | Free; no billing account needed for these APIs. |
| Pexels / Pixabay | Free keys with request limits (TECHNICAL_SPEC.md §3). |
| Gemini (optional) | Free tier with limits; Google may change it. |
| Electricity and your computer's time | The only real cost: AI and rendering keep the CPU busy (a 1-minute generated video takes ~3–5 minutes for the script and ~1.5 minutes to render on the test PC). |
| Backups | Free with your own drive; any cloud storage you choose has its own price. |
